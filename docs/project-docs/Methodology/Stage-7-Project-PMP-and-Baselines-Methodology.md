# Stage 7: Project (PMP & Baselines) — Methodology Guide

> **Purpose:** Approve each subsidiary management plan individually, then formalize the integrated Project Management Plan and its baseline — generated by tooling, never hand-authored — so Stage 8 has a real baseline to check readiness against.

> **Alignment:** PMBOK 8 Process 4.2 Develop Project Management Plan (also 5.1/6.1/7.1 Subsidiary Planning, ADR-013).

> **Authority:** FULL authority via `approve-subsidiary-plan` (per plan: `approve_plan`, `reject_plan`, `request_revision_before_decision`) and `approve-pmp` (`approve_pmp`, `reject_pmp`, `request_revision_before_decision`).

> **Authority in this repository:** the Sponsor decides every gate here. The PMP and its nine subsidiary plans are **generated by the `pmbok-planning` skill / `scripts/orchestrate_pmbok.py`** from templates and the approved Stage 6 scope. A standard that must hold in every run belongs in the template, then the plan is regenerated — it is never hand-edited after generation ([[feedback_pmbok_documents_generated_by_tooling]]).

---

## 1. Overview

### 1.1 Position in the Chain

```
Stage 6 (Requirement) — approved ADR/BRD/FDD/Stories supply scope and WBS
    ↓
Stage 7a: each subsidiary plan, approved individually (approve-subsidiary-plan, ADR-013 §4.2)
    ↓
Stage 7b: the integrated PMP, formalized on top of them (approve-pmp)
    ↓
Stage 8 (Implementation Readiness) — checks the formalized baseline, never writes it
```

### 1.2 Inputs

| Input | Source | Mandatory |
|---|---|---|
| Approved ADR/BRD/FDD/Stories for the epics this baseline covers | `docs/adr/`, `docs/project-docs/Business-Requirements/`, `docs/project-docs/Functional-Design/`, `docs/user-stories/` | Yes |
| `Scope-WBS-Dictionary.md` | `docs/project-docs/management-plans/scope-baseline/foundation/` | Yes |
| Prior baseline (if amending/incrementing) | `docs/project-docs/Project-Management-Plan.md`, `docs/project-docs/history/PMP-BL-*/` | If phase 2+ |

### 1.3 Outputs

| Output | Destination | Governed |
|---|---|---|
| Nine subsidiary management plans | `docs/project-docs/management-plans/` | Yes (via `approve-subsidiary-plan`, each) |
| Integrated Project Management Plan | `docs/project-docs/Project-Management-Plan.md` | Yes (via `approve-pmp`) |
| New baseline id | `Project-Management-Plan.md` frontmatter `pmp_baseline`, and `docs/project-docs/history/PMP-BL-<old>/` snapshot | Yes |

### 1.4 Success Criteria

Stage 7 is complete when:
- [ ] All nine subsidiary plans are individually approved
- [ ] The integrated PMP is approved and its baseline id matches the frontmatter and Project-Status-Register.md
- [ ] A frozen snapshot of the prior baseline exists under `docs/project-docs/history/`
- [ ] Stage 8's readiness gate can now run against this baseline

## 2. Process

### Step 1: Generate, don't hand-author

Run the `pmbok-planning` skill (or `scripts/orchestrate_pmbok.py`) against the approved Stage 6 scope and the current templates. If a plan needs a new standing rule, change the template, not the generated output — a hand-edit to a generated plan is immediately stale the next time it regenerates.

### Step 2: Submit each subsidiary plan for `approve-subsidiary-plan`

Run the policy per plan (Scope, Schedule, Cost, Quality, Risk, Resource, Communications, Procurement, Stakeholder Engagement — nine total). Each gets its own recommendation, Sponsor decision, and episode.

### Step 3: Submit the integrated PMP for `approve-pmp`

Once all nine subsidiary plans are approved, formalize the integrated PMP. This authorizes the baseline id (for example `PMP-BL-v1.1.0`) and, per its own action description, authorizes drafting the next cycle's ADRs/BRDs/FDDs/Stories (Stage 6 for the next epic set).

### Step 4: Snapshot and record

Freeze the prior baseline under `docs/project-docs/history/PMP-BL-<old-version>/` before or alongside formalizing the new one. Record the new baseline id, the episode, and the version bump rule (ADR-008 §4.6.1, ADR-037: patch for design-time corrections, minor for an execution adaptation, major for an architectural change) in Project-Status-Register.md.

## 5. Common Pitfalls

| Pitfall | Mitigation |
|---|---|
| Hand-editing a generated PMP or subsidiary plan | Put the standard in the template; regenerate |
| Treating a named future baseline id as already formalized | Check `approve-pmp` has actually run, not just that a target id was set by a Phase Close Decision |
| Skipping a subsidiary plan's individual approval and only approving the integrated PMP | ADR-013 §4.2 requires each subsidiary plan's own gate before PMP formalization |
