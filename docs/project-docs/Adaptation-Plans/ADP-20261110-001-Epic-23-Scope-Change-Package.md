## 2. Effort estimate (condition 3)

**Basis.** The approved Phase 2 milestones give person-days per story: M6 Epic 14 7.5 pd for 6 stories (1.25), M7 Epic 18 6.5 pd for 6 (1.08), M8 Epics 16 and 21 8.0 pd for 13 (0.62), M9 Epics 22 and 38 5.5 pd for 13 (0.42). Across all four milestones: 27.5 pd for 38 stories, **0.72 pd per story**. The early epics cost more per story than the later ones because the loop and tooling were still being built.

| Case | Rate | Epic 23 (7 stories) |
|---|---|---|
| Low | 0.72 pd per story (Phase 2 average) | 5.0 pd |
| **Planning value** | 1.0 pd per story (between the average and M6/M7) | **7.0 pd** |
| High | 1.25 pd per story (M6, the heaviest epic) | 8.75 pd |

Why not the low case: Epic 23 is new numerical code (a Bradley-Terry fit, a Laplace variance, pair selection), and Story 23.1 has a performance target the prototype misses (section 4). Why not the high case: the contracts, fixtures and review loop exist now, and Epic 23 reuses `pairwise.py`.

**Planning value: 7.0 pd, range 5.0 to 8.75 pd.** Hours: the cost plan values 30.0 pd at €15,300 of labour, so €510 per pd.

## 3. Schedule effect

Epic 23 depends on Epic 18 (`pairwise.py`), which is implemented. It does not depend on Epics 16, 21, 22 or 38, so it can run alongside the remaining Phase 2 work. The proposal places it as a new milestone **M9b** between M9 and M10.

| Option | Placement | Critical path | Effect |
|---|---|---|---|
| **A (recommended)** | New milestone M9b before M10, on the critical path | 30.0 pd to 37.0 pd | +7.0 pd, about +1.4 weeks at 5 pd per week |
| B | In parallel with M9, off the critical path | 30.0 pd, if 1.0 pd of float absorbs the join | Not credible: one maintainer, so parallel work is serial in practice |

Phase 2's M6 to M9 are already done, so M9b's start is now, not a forecast. The estimate error (5.0 to 8.75 pd) moves the Phase 2 completion date by about 1.4 weeks either way.

**Reserve.** The 5.0 pd schedule reserve `SR-P2-M10` and the 12.5 pd risk contingency are not drawn down by this proposal. Drawing on either needs a separate, explicit Sponsor decision. The recommended path adds a new baseline line for M9b, so the reserve stays whole for M10.

## 4. The less-than-5-ms target (condition 4)

The target stays: median fit time under 5 ms for N up to 100 (BRU-023-04, Story 23.1 AC_8). The prototype measured 98 ms at the default iteration cap, so the target is **not met today**.

Verification plan:

1. Story 23.1 is written RED first: the timing assertion fails on the prototype, then must pass on the implementation.
2. The timing test uses the median of repeated runs on fixed seeded input, so the result is reproducible.
3. If the first implementation misses the target, the story time-boxes a vectorized `numpy` rewrite at **1.5 pd**. That spike is inside the 7.0 pd planning value and the 8.75 pd high case, not extra.
4. **Fallback.** If the target still cannot be met inside the time-box, the story stops and returns to the maintainer as a requirement change request. The target is not relaxed inside the story.

The labour value is €510 per pd. This is an economic shadow valuation (cash outlay €0), as in the approved Cost-Management Plan.

Proposed cost baseline: Phase 2 economic valuation moves from €19,175 to **€22,745** (adds €3,570), and the budget including the €2,550 management reserve moves from €21,725 to **€25,295**. The €300 cash ceiling is unchanged because Epic 23 needs no external spend.
